# 发布指南 · 让朋友在微信里点开就玩

> 适用版本：1.11　更新时间：2026-10-24

## 结论先行

| 方案 | 花费 | 上线耗时 | 国内微信访问 | 支持联机 |
| --- | --- | --- | --- | --- |
| **A. GitHub + Zeabur（推荐）** | 免费起步 | 10 分钟 | 好（香港节点） | ✅ |
| B. 腾讯云轻量服务器·香港 | 约 ¥30/月 | 30 分钟 | 最稳 | ✅ |
| C. GitHub Pages（纯静态） | 免费 | 5 分钟 | 一般 | ❌ 仅单机 |
| D. Render 免费档 | 免费 | 15 分钟 | 一般 | ✅ 但会休眠 |

**常见疑问：GitHub 可以部署吗？** 可以，但要分两半说：GitHub **Pages** 是纯静态托管，只能放**单机版**（联机的 `room.html` 在上面连不上后端）；要跑联机，正确姿势是**代码放 GitHub + Zeabur 这类平台跑 Node 服务器**，仓库推送后部署/更新都是点几下的事。

## 第 0 步：把代码推到 GitHub（方案 A 的前置）

仓库已在本机初始化并完成首次提交，只需三步：

1. 在 GitHub 上新建一个空仓库（如 `dezhou-poker`，Public 即可——代码里没有任何密钥）。
2. 本机执行（把 `<你的用户名>` 换掉）：
   ```bash
   cd D:/Dev/code/dezhou-v2
   git remote add origin https://github.com/<你的用户名>/dezhou-poker.git
   git push -u origin master
   ```
   推送时会弹 GitHub 登录（或要求 Personal Access Token）。
3. 可选：推送前先 `git config user.name "你的名字"`、`git config user.email "你的邮箱"`，GitHub 上的提交头像就能对上。

## 方案 A：Zeabur 部署（GitHub 导入，推荐）

Zeabur 从 GitHub 仓库识别 Node 项目并自动执行 `npm start`，香港节点免备案，自动 HTTPS，国内微信可直连。

1. 打开 [zeabur.com](https://zeabur.com)，用 GitHub 账号登录。
2. **New Project**（区域选 **Hong Kong**）→ **Add Service → Git** → 选刚推送的仓库 → Zeabur 识别到 `package.json` 直接启动，无需任何配置。
3. 服务页 → **Networking** → **Generate Domain**，得到 `xxxx.zeabur.app`（自动 HTTPS）。
4. 微信里发两个链接：
   - **联机开黑**：`https://xxxx.zeabur.app/room.html` —— 建房后把带 `?room=房间号`（4 位数字）的链接发到群里，朋友点开 → 填昵称 → 默认上桌，九个座位随便换。
   - 单机练习：`https://xxxx.zeabur.app/play.html`
5. 以后更新代码：本地 `git push` 一次，Zeabur 自动重新部署。

> Zeabur 免费额度对朋友局的小服务一般够用；若控制台提示额度不足，可升最低档，或换方案 B。

## 方案 B：腾讯云轻量服务器·香港（最稳）

1. 购买**轻量应用服务器**，地域**中国香港**，镜像 Ubuntu 22.04（新用户常有约 ¥99/年 活动机）。无需备案。
2. 上传项目并装 Node：
   ```bash
   # 本机
   scp -r dezhou-v2 root@<服务器IP>:/opt/dezhou
   # 服务器上
   apt update && apt install -y nodejs npm caddy
   ```
3. systemd 常驻：
   ```bash
   tee /etc/systemd/system/poker.service <<'EOF'
   [Unit]
   Description=Yehang Poker server
   After=network.target
   [Service]
   WorkingDirectory=/opt/dezhou
   ExecStart=/usr/bin/node server/server.js
   Environment=PORT=8080
   Restart=always
   [Install]
   WantedBy=multi-user.target
   EOF
   systemctl enable --now poker
   ```
4. Caddy 反代（配一个 ~¥50/年 域名即自动 HTTPS）：
   ```
   你的域名 {
     reverse_proxy 127.0.0.1:8080
   }
   ```
   没有域名也可以先用 `:80` + IP 访问 `http://<服务器IP>/room.html`。
5. 腾讯云控制台 → 防火墙 → 放行 80 / 443。

## 方案 C：GitHub Pages（只能放单机）

GitHub Pages 是纯静态托管，**联机的 `room.html` 在这里连不上后端**。放单机版：

1. 仓库 **Settings → Pages** → Source 选 `Deploy from a branch` → 分支 `master`、目录 `/dist` → Save。
2. 几分钟后得到 `https://<你的用户名>.github.io/dezhou-poker/`，单机在 `/play.html`。
3. 以后 `git push` 自动更新。

## 方案 D：Render 免费档（联机可用，但会休眠）

[render.com](https://render.com) 用 GitHub 登录 → New Web Service → 选仓库 → Build 留空、Start 命令 `npm start` → 免费实例。

注意：免费实例 **15 分钟没人访问就休眠**——再打开要等约 1 分钟冷启动，且**内存里的房间全部清空**（打一半的牌局作废）。只适合"约好时间、进来看一眼"的轻度用法；认真玩用 A 或 B。

## 部署后 30 秒自检清单

- [ ] 微信打开 `/room.html`：能建房，房间号（4 位数字）出现
- [ ] 两台手机分别进房、开局、各拿各的底牌、轮流行动
- [ ] 点空位能换座；结算面板「去围观」后点空位能回来
- [ ] 断网重进（或杀掉微信重开链接）能回到原座位
- [ ] 分享卡片：标题 + 水果缩略图正常

## 微信传播注意事项

- 定位是**免费娱乐、无真钱、无转账、无抽奖**，正常分享不会被封；文案避免「赌、赢钱、提现」等字眼。
- 链接出现「非微信官方网页」提示时点**继续访问**即可；域名万一被彻底封禁，换平台/换域名重新发布（方案 B 自有域名最抗封）。
- 不要把 H5 冒充"微信小游戏"提交审核——棋牌类目个人主体不可行，链接分享不需要审核。

## 联机服务的运行边界

- 房间数据在**内存**里：服务器重启/平台休眠后所有房间消失（进行中的牌局作废），刻意保持简单；朋友局够用，正式运营需要另做持久化。
- 每手 60 秒思考时间，超时自动过牌/弃牌；掉线座位保留 5 分钟。
- 单房间 2–9 人；加入默认上桌，随时点空位换座或去围观（筹码暂存，回来即恢复）。
