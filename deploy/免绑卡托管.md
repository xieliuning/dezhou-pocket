# 免绑卡托管 · 没有信用卡也能和朋友联机

> 更新时间：2026-10-25　适用版本：1.11
>
> 背景：Render / Railway / Fly.io / Heroku 的免费档都要先绑银行卡做风控；
> 而 **Supabase、Cloudflare、Zeabur 的免费档不绑卡**。

---

## 一、结论先看

| 路线 | 要改多少代码 | 电脑要开着 | 国内能不能开 | 稳定性 | 什么时候用 |
| --- | --- | --- | --- | --- | --- |
| **A1. 本机隧道 · cloudflared** | **0 行** | **要** | ✅ 能 | 会掉线（实测） | 今晚临时开一局（**国内首选**） |
| A2. 本机隧道 · localtunnel | 0 行 | 要 | ✅ 能 | 会掉线（实测） | 没装 cloudflared 时的兜底 |
| **B. Cloudflare Workers + Durable Objects** | 服务端约 200 行 | 不要 | ❌ **被拦** | 好 | 长期免费玩（**海外首选**） |
| **C. Supabase** | 客户端 1000+ 行 + 服务端重写 | 不要 | ✅ 能 | 好 | 需要存档、排行榜、跨设备战绩 |
| D. Zeabur Free | 0 行 | 不要 | ✅ 能 | 好 | 注册不强制绑卡就能直接用 |

**一句话回答「Supabase 可以吗」：可以，但它不是「换个托管商」，是「把后端重写一遍」——
工作量最大、见效最慢。除非你还想做战绩存档/排行榜，否则不建议从这里起步。**

### ⚠️ 一个必须先知道的前提：`workers.dev` 在中国大陆打不开

2026-10-25 实测（国内网络）：

| 检查 | 结果 |
| --- | --- |
| `yehang-poker.yehangpoker.workers.dev` 的 DNS 解析 | ❌ 解析到 `157.240.8.41`（Facebook 网段）、`199.59.149.207`（Twitter 网段）——**典型 DNS 污染** |
| 用真实 Cloudflare IP 直连 + 正确 SNI | ❌ TLS 握手直接失败（`tls=0.000000s`）——**SNI 层面被拦** |
| 同一个网络下 `x.trycloudflare.com` 的 TLS 握手 | ✅ 正常（Cloudflare 回 530 = 隧道未开，说明域名和 SNI 都通） |
| `api.cloudflare.com` / `www.cloudflare.com` | ✅ 正常（所以授权、上传、部署都正常） |

结论：**Worker 本身部署得好好的，是 `workers.dev` 这个域名被拦**。
所以国内用户要玩，得走下面两条之一：

1. **cloudflared 快速隧道**（`*.trycloudflare.com`）→ 免费、不绑卡、**国内能开**、
   访客不用输密码；代价是电脑得开着，隧道重启地址会变。
2. **给 Worker 绑自己的域名** → 24 小时在线、地址永久不变、国内也能开；
   代价是要买一个域名（几十块一年）。

海外的朋友、或者不介意用代理的用户，直接用方案 B 的 `workers.dev` 地址即可。

## 二、路线 A：本机隧道（0 行改动，今晚就能玩）

思路：牌局服务器照旧跑在你自己电脑上，用一个隧道工具把本机 8080 端口映射成公网 HTTPS 地址。
朋友打开那个地址就能进房，**服务端一行代码都不用改**。

### 启动方式

项目自带一键工具：

```powershell
node tools/tunnel.js
```

它会自动检查 8080 端口、没在跑就起 `node server/server.js`，再拉起隧道，最后打印：

```
  公网地址已就绪（cloudflared）：

    联机开黑  https://abc-def-ghi.trycloudflare.com/room.html
    单机练习  https://abc-def-ghi.trycloudflare.com/play.html
```

默认优先用 **cloudflared 快速隧道**（`*.trycloudflare.com`，国内能开、访客不用输密码）；
没装 cloudflared 就自动退回 **localtunnel**（`*.loca.lt`，纯 npm 依赖、永远可用，
但访客第一次打开会看到「隧道密码」页，要填你的公网 IP，例如 `14.220.182.152`）。

装 cloudflared 见 `tools/README-cloudflared.md`（下载一个 exe 放到 `tools/bin/` 即可）。
想强制用 localtunnel：`node tools/tunnel.js --provider localtunnel`。

两条自愈机制（两种隧道都有）：

- **进程退出** → 3 秒后自动重开隧道（地址会变，旧链接失效，记得重新发群）
- **链路假死**（进程还在但地址已经打不通，实测很常见）→ 每 45 秒探一次，
  连续 3 次失败就掐掉重开

也可以手工分两步：

```powershell
node server/server.js
tools\bin\cloudflared.exe tunnel --url http://127.0.0.1:8080 --protocol http2
```

把打印出来的地址发到群里，朋友打开 `<地址>/room.html` 即可。

### 2026-10-25 本机实测结果

| 项目 | 结果 |
| --- | --- |
| HTTP 静态页 | ✅ `/room.html`、`/js/room.js`、`/js/config.js`、`/css/room.css`、`/js/poker.js` 全部 200 |
| WebSocket 升级 | ✅ `HTTP 101 Switching Protocols` |
| 牌局协议 | ✅ 服务端返回 `{"t":"pong"}` |
| 浏览器端建房 | ✅ 经公网隧道建出房间 2918，状态行显示「当前连接：https://xxx.loca.lt（已连接）」 |
| **双客户端端到端** | ✅ 两个独立客户端经公网隧道同房：A 建房 → B 加入（座位 0 / 1）→ 双方都看到 2 人入座 → 开局进入 preflop → **各拿 2 张底牌** → A 视角看不到 B 的底牌 → A 弃牌后双方都收到 handover 状态、底池 60 |
| 朋友侧首次访问（localtunnel） | ⚠️ localtunnel 会弹「隧道密码」页，要求填**你的公网 IP**（每 7 天每个客户端 IP 一次）；**cloudflared 没这个问题** |
| 长时间稳定性 | ⚠️ 实测 2～20 分钟不等会出现 502 / 超时，客户端进程不会自愈；`tools/tunnel.js` 会自动重开隧道换一个地址 |

> 也就是说：**隧道会在牌局中途掉**。真人局建议先约好时间、准备好再开，
> 或者用下面的 Cloudflare Workers 方案（不依赖本机、不掉线）。

### 已知边界

- **电脑必须一直开着**且不能休眠，关机/断网 = 牌局中断。
- localtunnel 会把你的**公网 IP 暴露给每个访客**（当密码用）。用 cloudflared 就没这问题。
- 隧道地址是随机的，每次重启都变。
- 房间数据本来就在内存里，隧道断 = 房间清空。
- **隧道会中途掉线**（实测 2～20 分钟），`tools/tunnel.js` 会自动重开，但换地址后朋友手里的旧链接就失效了。

> 适合场景：今晚临时开一局。**不适合长期使用。**

## 三、路线 B：Cloudflare Workers + Durable Objects（推荐长期用）—— **已实现**

Cloudflare 免费档**不绑卡**（注册只要邮箱），且 Workers 原生支持 WebSocket。

### 免费档额度（官方文档核实）

| 项目 | 免费档 |
| --- | --- |
| Workers 请求数 | 100,000 / 天 |
| Workers 单请求 CPU | 10 ms |
| Workers 内存 / 包体积 | 128 MB / 64 MiB |
| Durable Objects 请求数 | 100,000 / 天 |
| Durable Objects 时长 | 13,000 GB-s / 天 |
| Durable Objects 存储 | 仅 SQLite 后端 |
| 静态资源（Workers Static Assets） | 20,000 文件 / 版，单文件 25 MiB |

WebSocket 消息按 20:1 折算请求数。

### 代码已经写好了

| 文件 | 作用 |
| --- | --- |
| `cf/worker.js` | Worker 入口：`/ws` 的 WebSocket 升级转给 Durable Object，其余走静态资源 |
| `cf/poker-hall.js` | Durable Object「牌局大厅」：`server/server.js` 的房间逻辑整体移植版 |
| `wrangler.toml` | 部署配置：DO 绑定 + `dist/` 静态资源 |
| `js/poker.js` | **原样复用**，牌局引擎一行没动 |
| `js/room.js` | **原样复用**，客户端一行没动（协议完全不变） |

移植时改掉的东西：

- `crypto.randomInt` / `randomBytes` → Web Crypto 的 `crypto.getRandomValues`
- 静态文件 `fs.readFile` → Workers Static Assets 直接挂 `dist/`（前端和牌局服务器**同源**，
  不用再配 `?server=`）
- 回合 / 升盲的 `setTimeout` → Durable Object `alarm`（同一时刻只保留一个 alarm，
  取「回合到期 / 升盲到期 / 下次巡检」里最早的那个）
- 房间状态每次变更都写进 DO 的 SQLite 存储（key = `room:<房间号>`），
  Worker 重启后房间还在，玩家凭 token 回来还是原座位
- 全部房间装在**一个** Durable Object 实例里：单线程串行，**并发行动不会打架**
- WebSocket 走 **Hibernation API**：`acceptWebSocket(ws, ["poker"])`，
  玩家身份存在 WebSocket attachment（`ws.serializeAttachment`）里。
  实例被回收再拉起时，连接和身份都还在，牌局中途不会断。
  > 注意：attachment 方法挂在 **WebSocket 对象**上（`ws.serializeAttachment` /
  > `ws.deserializeAttachment`），不在 `ctx` 上——`ctx` 只有 `acceptWebSocket` /
  > `getWebSockets` 等方法。

### 部署步骤

```bash
npx wrangler login      # 首次：浏览器授权；Cloudflare 账号注册不绑卡
npx wrangler dev        # 本地调试（自带 workerd，不用连公网）
npx wrangler deploy     # 部署，得到 https://yehang-poker.<你的子域>.workers.dev
```

部署完把 `https://yehang-poker.<你的子域>.workers.dev/room.html` 发到群里，
建房后把带 `?room=房间号` 的链接发出去即可。**同源部署，不需要配服务器地址。**

> 国内网络的小坑：Node 默认优先 IPv6，若本机 IPv6 通路不通，`wrangler` 会报
> `Unable to resolve Cloudflare's API hostname`。加一个环境变量即可：
>
> ```powershell
> $env:NODE_OPTIONS = "--dns-result-order=ipv4first"
> npx wrangler deploy
> ```
>
> 首次部署前还要先注册一个 workers.dev 子域名，非交互命令行里 wrangler 不会自动注册，
> 直接调接口更快（`PUT /accounts/<账号ID>/workers/subdomain`，body 为 `{"subdomain":"你的子域"}`）。

### 绑自定义域名后怎么用

```toml

  { pattern = "poker.你的域名.com", custom_domain = true }
]
```

```powershell

npx wrangler deploy
```

部署完 `https://poker.你的域名.com/room.html` 就是给朋友的链接，**国内也能开**。

## 四、路线 C：Supabase 评估（能做，但最费工）

### 为什么它不是「换个托管商」

本项目的牌局服务器是**一个长连接 WebSocket 服务**（`server/server.js` + `server/ws-lite.js`）。
Supabase 没有「托管我的 Node 长连接服务」这个产品：

1. **Edge Function 不支持 WebSocket 升级。** 只能收普通 HTTP 请求。
   → 客户端 `js/room.js` 的 WebSocket 传输层**必须重写**：
   收状态改用 **Realtime Broadcast** 订阅，发动作改用 HTTP（`supabase.functions.invoke`）。
2. **房间状态必须从内存搬到 Postgres。** Edge Function 里拿不到交互式事务锁，
   只能用**乐观锁**：读 `rooms.state`(JSONB) + `version` → 在 JS 里跑 `js/poker.js` 算出新状态
   → `UPDATE ... WHERE version = $old` → 影响行数为 0 就重试。
3. **客户端要引入 `supabase-js`**（CDN 或打包），并多一套配置（项目 URL + anon key），
   目前 `js/config.js` 只有一个 `window.YEHANG_SERVER`，需要扩展。

### 成本估计

| 项 | 量级 |
| --- | --- |
| `js/room.js` 传输层重写 | ~300 行改动（1058 行里的核心部分） |
| 新建 `supabase/functions/poker/` | ~400 行（房间管理 + 动作校验 + 广播） |
| SQL schema（rooms 表 + RLS 策略） | ~80 行 |
| 牌局逻辑 `js/poker.js` | 0 行（纯逻辑，可直接复用） |
| 回归测试 | 协议从 WebSocket 换成 HTTP+Realtime，`tools/test-server.js` 需要重写 |

### 免费档的坑

- 免费档项目**连续 7 天低活跃会被暂停**（Pro 计划才保证不暂停）。
  好友局间隔超过一周就可能需要手动恢复项目。
- 2 个免费项目、500 MB 数据库——牌局数据量很小，够用。

### 什么时候值得做

只有当你还想加**跨设备战绩存档、排行榜、账号体系**时，Supabase 的 Postgres 才体现价值。
纯联机牌局，它比方案 B 多花好几倍工，换来的只是「一个更陌生的技术栈」。

## 五、选型建议

- **今晚就想和朋友玩** → 路线 A（`node tools/tunnel.js`，优先 cloudflared → `*.trycloudflare.com`），
  10 分钟内开桌，接受电脑不能关、地址会变。
- **想长期稳定免费玩** → 路线 B（Cloudflare Workers，已部署在
  `https://yehang-poker.yehangpoker.workers.dev`），一次性写 ~200 行服务端，之后免费无限用，
  电脑关掉也能玩，房间还能存盘。**国内要能开，就再绑一个自己的域名。**
- **想要战绩存档/排行榜** → 路线 C（Supabase），但先按 B 把联机跑通，再加存档层。

不管选哪条，**前端和牌局服务器都可以分开托管**：
`room.html` 支持 `?server=` 参数、浏览器本地记住地址、`js/config.js` 写死站点默认值，
三种方式优先级从高到低，详见《发布指南》的「网页版与牌局服务器分开托管」一节。
